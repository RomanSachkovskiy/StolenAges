# AGENTS.md — обязательные инструкции для Codex

## Цель

Создать и довести до играбельного релиза `Stolen Ages v0.1.0`, браузерную одиночную стратегию с тремя эпохами и территориальным расширением. **Не останавливаться после создания скелета, «демо» или статической картинки**. Следовать `docs/GAME_SPEC_V0.1.md`.

## Язык и рабочий процесс

- Общайся с пользователем на **русском**. Программный код, имена типов/переменных, сообщения коммитов — на английском. Интерфейс RU по умолчанию, EN как дополнительная локализация по мере реализации.
- Сначала проверь фактическое состояние **всего репозитория**: `git status`, текущую ветку/HEAD, дерево файлов, README и конфиги. Не принимай старые сводки за актуальное состояние. Перед важными правками и в конце проверяй diff.
- Не спрашивай по каждому решению: используй значения по умолчанию из GDD, документируй существенные отклонения.
- Используй TypeScript strict; игровая логика должна быть отделена от Phaser и DOM и тестироваться в Node без браузера.
- Все случайные решения через seeded PRNG; не использовать `Math.random()` в domain systems. Единственный вход изменения GameState — валидированные `GameCommand`.
- Никаких моков, которые в итоге делают UI «кликабельным, но неработающим»: действия должны менять реальное состояние и правила игры.
- Каждый этап заканчивай `typecheck`, `test`, `build` и сохранением кода. Не оставляй поломанный `main`.
- Сохраняй последовательность коммитов, подготовь PR с описанием, скриншотами и результатами проверок, если облачная среда работает по модели PR.
- Не сообщай, что деплой успешен, пока GitHub Actions/URL действительно не подтверждены.

## Архитектурные запреты

- Никакой игровой логики внутри обработчиков Phaser Scene или DOM-компонентов.
- Не мутируй DomainState извне reducer/engine. Не привязывай игровую логику к FPS, `setTimeout` или реальному времени.
- Не смешивай настоящее/будущее/прошлое в один неявный массив. Каждое изменение эпохи и «эхо» должно быть явным и тестируемым.
- Не включай сетевой multiplayer, тяжёлые 3D-ассеты, платные сервисы, собственный backend или полнофункциональный RTwP в v0.1.
- Не добавляй npm-зависимости без необходимости; не копируй чужие игры и чужие изображения без лицензии.

## Что реализовать по порядку

1. Bootstrap Vite + Phaser 4 + TS + Vitest; CI; GitHub Pages base.
2. Чистое детерминированное игровое ядро, данные карты, переходы хода, тесты.
3. Полноэкранная карта / зум / панорама, топ- и нижняя панели, контекстные действия.
4. Экономика, аванпост, постройки, рост поселений, связь прошлого с будущим.
5. Армии-человечки, перемещения, бой, осада, исследования.
6. ИИ двух соперников, стратегическая оценка, завершение матча.
7. Онбординг, сейв/лоад, настройки, локализация, мобильный portrait UX.
8. QA на ПК/телефоне, доступность, финальная балансировка, CI и Pages.

## Definition of Done

Все обязательные acceptance criteria из GDD пройдены; игра запускается, сохраняется и имеет результат, две ИИ-фракции ходят, три эпохи влияют на игру, телефон пригоден к управлению пальцем, сборка работает на Pages. В конце дай краткий отчёт: коммиты, тесты, Pages URL, найденные ограничения и следующие задачи.
