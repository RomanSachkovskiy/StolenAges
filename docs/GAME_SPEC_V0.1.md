# STOLEN AGES — Game Design & Technical Specification v0.1.0

**Назначение:** источник истины для Codex при создании **первой полностью играбельной** браузерной версии. Документ описывает цель, неизменяемые требования, конкретные значения по умолчанию, границы объёма, модель данных, UI, правила, баланс, тесты, CI и выпуск. Все значения, не обозначенные как «обязательно», являются **первоначальными настройками для плейтеста**, а не измеренной истиной.

- **Название продукта:** Stolen Ages (рабочее); русская концепция «Вор времени».
- **Версия:** 0.1.0. Старые обозначения Eraforge v0.4–v0.7 относятся к концептам и экспериментам, а не к текущей кодовой базе.
- **Платформа:** браузерная одиночная игра без сервера, GitHub Pages, desktop landscape и mobile portrait.
- **Основная идея:** игрок расширяет территорию и развивает города сразу в трёх связанных эпохах. Выгодная инвестиция в прошлом создаёт «эхо» в настоящем и будущем, меняя доступные стратегии.
- **Целевой сценарий:** одна законченная партия за ~20–25 минут у опытного игрока на ПК (см. расчёт ниже); короткие партии возможны позже.

## 1. Границы первой версии

### Обязательная v0.1

1. Главное меню (Новая игра/Продолжить/Как играть/Настройки), экран результатов и рестарт.
2. Одна фиксированная, читаемая карта из **18 регионов**, непрерывные проходы, реки, мосты, горы, леса, ресурсные точки, города и границы контроля; одна и та же география в 3 эпохах.
3. **3 эпохи:** Past / Present / Future, переключаемые верхним контролом. Каждая эпоха имеет собственный слой владельцев, зданий и армий. Действия в Past дают прозрачные бонусы в Present/Future, в Present — в Future.
4. **3 фракции:** игрок + два независимых ИИ. У каждой стартовый город и владения; нейтральные регионы. Различимые цвета и формы меток.
5. Ресурсы, производство, строительство, улучшение 4 уровней поселений, исследование технологий, армии, перемещения, захват нейтральных и вражеских регионов, укрепления и осада.
6. Внятная пошаговая система для v0.1: **3 очка действий на ход игрока**, затем ход двух ИИ, доход/производство и обновление эффектов. **До 20 полных раундов** (можно закончить раньше).
7. Минимальные, но реальные тактические альтернативы: мирное расширение, война, оборона, экономика, технологии и временные «эхо».
8. Простая стилизованная **2D-графика** (SVG-подобные процедурные фигуры/простые спрайты). Армии изображаются **человечками**, не эмодзи и не одними значками. Рисунки различаются по эпохам, классу войск, уровню 1–4.
9. Камера pan / pinch zoom / wheel zoom, выбор регионов и армий, короткие анимации, отключаемые в настройках.
10. Адаптивность: ПК в горизонтальной ориентации, телефоны **в вертикальной** без требования переворота. Карта почти на весь экран, никакой постоянной боковой панели.
11. Сохранение/продолжение через localStorage с версией формата, фиксированный seeded RNG, тесты ядра, CI и деплой GitHub Pages.

### Не входит в v0.1

Сетевая игра и сервер; генерация бесконечных миров; прогрессия мета-аккаунта; сюжетные кампании; real-time-with-pause в промышленном виде; физическая симуляция снарядов; 3D; сложная дипломатия; десятки классов войск; локализации кроме RU (EN — желательно, но не блокер); серверные сохранения; покупки. **Не добавлять их ценой неполной основной игровой петли.**

## 2. Основная игровая петля

`Новая партия → выбор эпохи → выбор региона/города/армии → оценка ресурсов и угроз → одно из действий → 0..3 AP → Завершить ход → ИИ → производство и строительство → события/результат → новый ход`.

Игроку каждый ход нужно решать: **строить сейчас ради прибыли позже**, **взять свободную землю до противника**, **усилить оборону**, **нанести удар**, или **изменить прошлое ради бонуса в будущем**. За каждое действие должна быть показана цена, ожидаемый эффект и причина недоступности при блокировке.

Победа/поражение обязательны; игра должна оставаться интересной за счёт конфликта за ограниченные переходы, ресурсные регионы и сильные точки.

## 3. География и карта

### 3.1. Стартовые данные

- Один воспроизводимый world seed и фиксированный геометрический граф из **18 регионов**, расположенных **достаточно далеко друг от друга на холсте**; камера сначала показывает стратегическое ядро, не все поселения впритык. Мир должен быть заметно шире/выше viewport.
- Размер мировых координат по умолчанию **2800 × 1900**. Регион имеет polygon/center и `neighbors: string[]` для смежности; дороги/мосты обозначают особые рёбра. Все рёбра симметричны и проверяются валидатором.
- Типы регионов: `plain`, `forest`, `mine`, `farmland`, `river_crossing`, `mountain_pass`, `city`, `ruins`. Минимум 2 стратегических choke points, 4 ресурсных региона, 3 стартовые столицы и 3 нейтральных поселения, остальное — территории для расширения.
- Чёткое пространственное различие городов. Никаких плотных скоплений всех поселений в одной области. Не использовать пиктограммы как единственный способ различать владения: поддержать цвет, паттерн/рамку и подпись.
- Для каждой эпохи **те же 18 географических регионов**, но своя палитра и визуальное развитие. То есть 54 логических `RegionEpochState`, а не 54 отдельные карты.

### 3.2. Старт партий

- Игрок — **синяя/золотая** фракция, ИИ-1 — красная, ИИ-2 — фиолетовая, нейтрал — серая.
- В **каждой эпохе** у каждой фракции по **1 стартовой столице (ур.1)** в той же географической точке и **1 соседнему владению**. Остальные регионы нейтральны. При наличии одной и той же столицы в разных эпохах это три самостоятельных объекта состояния, но связанные историей.
- Все фракции стартуют с равной ценностью городов и примерно сопоставимым доступом к ресурсам; маршрут от стартового города к нейтральному ресурсу ≤2 рёбер.
- Общие запасы игрока на все эпохи: `food=12, wood=12, ore=8, energy=0, knowledge=3, influence=5`. Энергия начинает производиться в Future; технологии разблокируют её применение. Цифры для первой балансировки.
- У каждой фракции 1 отряд базовых войск в эпохе Past и по небольшому гарнизону городов Present/Future. Не создавать в начале десятки армий.

### 3.3. Панорама и камера

- Drag/pan мышью и одним пальцем по свободной поверхности. Wheel/pinch для zoom вокруг указателя/точки касания.
- Диапазон zoom по умолчанию **0.65–2.4** от базового масштаба; обрезка камеры по мировым границам. Кнопка «домой» центрирует на столице выбранной эпохи.
- Tap выбирает регион; второй tap по армии/строению открывает контекст. Drag более 8 px не считается кликом. Выбор сохраняется при переключении эпохи, если есть логический аналог региона.
- При открытии контекстной панели карта должна оставаться управляемой; не перекрывать её целиком.

## 4. Эпохи и временное эхо: точные правила v0.1

### 4.1. Отдельные состояния, общий граф

У каждого `regionId` есть независимые `regionStateByEpoch[Past|Present|Future]`. Игрок может переключаться между эпохами без расхода AP (просмотр). **Любое действие стоит AP глобально**, независимо от эпохи. Нельзя "бесплатно" накопить AP в каждой эпохе.

### 4.2. Причинность без парадоксов

В v0.1 изменение Past **не перекрашивает автоматически** собственность Present/Future: это быстро ломает баланс и делает тактические решения непредсказуемыми. Вместо этого используется ясный и тестируемый механизм **Temporal Echo**:

- `pastEcho(regionId, factionId) = 1`, если в Past данный регион **на момент подсчёта** принадлежит фракции и в нём есть аванпост/город/производственное здание. Иначе 0.
- `presentEcho(regionId, factionId) = 1`, если регион принадлежит фракции в Present и имеет **хотя бы одно** построенное здание. Иначе 0.
- Если тот же `regionId` контролируется фракцией в Present, `pastEcho` даёт **+1 к производству** основной добываемой единицы региона за ход (не более +1, независимо от числа построек).
- Если регион контролируется фракцией в Future, `pastEcho` даёт **+1 ресурс/ход**, а `presentEcho` — **дополнительно +1 ресурс/ход**. Если владельцы разных эпох различаются, эхо данной фракции не применяется: это не бесплатный захват территории.
- Всплывающие подсказки показывают «Эхо прошлого: +1 Wood/ход»; смена владельца или уничтожение соответствующего сооружения пересчитывает эффект со следующего income phase.
- Нет бесконечных циклов: Past → Present → Future только в одну сторону. Эхо вычисляется **без изменения исторических снимков**, не дублирует ресурсы при повторных пересчётах и сериализуется производными вычислениями.

### 4.3. Отличия эпох

- **Past:** деревянные постройки и солдаты со щитами/копьями/луками; основа — wood/food. Улучшения выглядят как домик → хутор → укреплённое поселение → деревянный город.
- **Present:** кирпич/камень, технические сооружения, бойцы с условным современным снаряжением. Основные wood/ore/food, сильнее защита.
- **Future:** неоновые/металлические формы, генераторы, футуристическая пехота, энергия и знания. Отражение технологии через разные спрайты, но единый игровой движок.
- В v0.1 разрешается строить/воевать в любой эпохе с первого хода — так игрок видит систему сразу. Ограничение ресурсов, AP и технологий обеспечивает реальные trade-offs. Блокировать целую эпоху до поздней игры нельзя.

## 5. Ресурсы, экономика, строительство

### 5.1. Запасы и доход

`Resources = { food, wood, ore, energy, knowledge, influence }`. Доход начисляется **один раз за полный раунд каждой фракции** после завершения её планирования, без дублей при рендере. Базовый доход каждого стартового города: `food +2, wood +1, knowledge +1`. Ферма +2 food, лесопилка +2 wood, шахта +2 ore, электростанция +2 energy только Future, академия +2 knowledge. Аванпост даёт +1 influence. `max(0, base + buildings + temporalEcho - armyUpkeep)` для каждого ресурса; upkeep: 1 food на каждые 2 активных армии (округление вверх), вне зависимости от эпохи. Не допускать отрицательных запасов; при нехватке еды армии получают маркер `undersupplied` и -15% боевой силы до восстановления.

### 5.2. Каталог построек (первоначальные стоимости)

| Здание | Эпохи | Стоимость | AP | Время v0.1 | Эффект |
|---|---|---:|---:|---|---|
| Farm | все | 3 wood | 1 | следующий income | +2 food |
| Lumber Mill | все | 3 food | 1 | следующий income | +2 wood |
| Mine | все | 3 wood +2 food | 1 | следующий income | +2 ore |
| Academy | Present/Future | 4 wood +3 ore | 1 | следующий income | +2 knowledge |
| Power Plant | Future | 4 ore +2 knowledge | 1 | следующий income | +2 energy |
| Watchtower | все | 3 wood +1 ore | 1 | сразу | +2 defense |
| Wall | все | 5 wood +3 ore | 1 | следующий income | +4 defense, добавляет siege requirement |
| Barracks | все | 4 wood +2 ore | 1 | сразу | позволяет вербовать армии |
| Outpost | все | 2 wood +2 influence | 1 | сразу | мирный захват прилегающей нейтральной территории (команда ClaimNeutral), +1 influence на своей территории |

Размещение: в одном регионе **до 2 зданий** плюс один гарнизон и один город (если на регионе есть город); Outpost учитывается как одно здание. `Farm` допустима на plain/farmland/city; `Lumber Mill` на forest/city; `Mine` на mine/mountain_pass; и т.д. В UI объяснять ошибки размещения. Улучшения городов не должны бесконечно умножать базовый доход.

### 5.3. Город 1→4

`UpgradeCity` стоит 1 AP, `wood/ore` по уровню: 1→2: 5/2; 2→3: 8/5; 3→4: 12/8 и `knowledge 5`. Рост меняет вид на карте и даёт `+1 food +1 knowledge` за новый уровень, защита `+2` за новый уровень, увеличивает лимит города на 1 гарнизон (опционально для v0.1). Одна столица каждой фракции на эпоху, остальные города могут быть улучшены только до ур.3. Здания не исчезают при улучшении.

### 5.4. Исследования

Одна технология разблокируется действием `Research` (1 AP) и стоимостью knowledge; стартовая очередь 5 технологий: `Agriculture I` (+1 к ферме), `Fortification I` (+1 wall/tower defense), `Logistics I` (второй марш/раунд одному отряду), `Military Training I` (+1 level при новом найме при наличии ресурсов), `Temporal Resonance I` (+1 к эху Future **глобально за максимум 2 региона**, жесткий cap). Каждая доступна один раз для фракции, доступность показывать в панели. Это многоразовые бонусы без сложного дерева для v0.1.

## 6. Территории, логистика, армии, бой

### 6.1. Мирный захват

- Территория должна быть `neutral` в **выбранной эпохе**, иметь соседний регион, контролируемый фракцией, и быть достижима по разрешённому ребру.
- `ClaimNeutral` стоит `1 AP + 2 influence + 2 wood`. В целевом регионе появляется outpost и он становится собственностью фракции в конце команды. Если там нейтральное поселение, игрок получает город ур.1.
- Вражеские регионы только военным путём. Нельзя мирно захватить регион без смежности, через непроходимое ребро или при дефиците ресурсов.
- На choke point допускается осада/боевой конфликт. Блокируемые проходы определены картой, а не произвольной визуализацией.

### 6.2. Отряды

В v0.1 два класса `infantry` (сильнее в защите) и `ranged` (сильнее в наступлении вне леса); четыре уровня улучшения; визуал для каждого класса×эры×уровня (24 комбинации допустимы как процедурные вариации базовых поз/амуниции). Отряд — одна логическая единица, изображаемая группой **2–4 маленьких людей** для читаемости. `recruit` на регионе с Barracks/стартовой столицей: 1 AP, `3 food +2 wood` для пехоты, `3 food +3 ore` для дальнего, создание с `strength=10`, `level=1`, `hp=10`, `movement=1 edge/turn`. `upgradeArmy`: 1 AP, 2 ore + 2 knowledge, максимум 4.

Ограничение v0.1: не больше **8 активных отрядов на фракцию** по всем эпохам — снижает нагрузку и хаос. Только один полевой отряд одной фракции на регион/эпоху; гарнизон города — отдельный защитный рейтинг и не требует бегущих спрайтов.

### 6.3. Движение

`MoveArmy` проверяет владельца, принадлежность эпохе, смежность/маршрут, supply и остаток movement. Разрешены переходы на соседнюю собственную/нейтральную область (нейтральная не становится автоматически своей). Движение в территорию соперника запускает `Attack` и стоит 1 AP; один отряд атакует один регион за команду. Для маршрутов >1 ребра — pathfinding по BFS/A* с ценой местности, исполнение по одному ребру; не телепортировать. Перенос войск между эпохами **не входит в v0.1**, визуальный переключатель эпох — не телепорт.

### 6.4. Боевые числа и воспроизводимость

Входы: атакующий `baseAttack=8`, защитник `baseDefense=6`; уровень `+2` за каждый сверх 1; `ranged +2 attack` на plain/farmland, `infantry +2 defense` в forest/mountain_pass; `Watchtower +2`, `Wall +4`, город `+2 per level`, гарнизон +2. Множитель недоснабжения `×0.85`. Один бросок seeded RNG для небольшой вариативности `±10%` (одинаковый seed + команды → одинаковый итог).

- `attackPower = round((8 + 2*(level-1) + classAttackModifier) * supplyModifier * rngFactor)`;
- `defensePower = 6 + 2*(level-1) + classDefenseModifier + terrainDefense + cityDefense + buildingDefense`;
- При `attackPower >= defensePower` защитник/регион захватывается, атакующий теряет `max(1, ceil(defensePower/4))` HP; если атакующий выжил, регион меняет владельца и строения (кроме стены, если осада уничтожила) переходят игроку.
- Если `attackPower < defensePower`, атакующий теряет `ceil((defensePower - attackPower)/2)+2` HP и отступает в исходный регион. Атакующий с `hp<=0` удаляется. Не допускаются отрицательные значения HP.
- Если есть Wall/Fortified city и атака не имеет достаточной силы, при первой атаке создаётся `siege` со счётчиком 1; осада увеличивает `siegeProgress` на 1 за каждый следующий `EndRound` при живой/неперемещённой блокирующей армии. На прогрессе ≥2 Wall теряет +4 defense, повторная атака может захватить. Во время осады защитник может нанести вылазку. На карте виден прогресс осады.

**Важно:** формулы стартовые. Тестировать, чтобы стартовая столица не захватывалась 1 базовым отрядом на первом раунде. Пользователь должен видеть подсказку ожидаемого результата до подтверждения атаки: «низкий/средний/высокий шанс» без ложной точности.

### 6.5. Анти-сноуболл и comeback

- Лимит 3 AP/ход не зависит от размера империи.
- Содержание армии, лимит 8 отрядов, кап эхо и ограничение построек на регион снижают снежный ком.
- Один раз за игру, если фракция владеет <25% от числа владений лидера после 6-го раунда, открывается бесплатный оборонный `Last Stand`: +3 к защите стартовой столицы на 2 раунда (не стакается); явно объяснять в UI.
- ИИ оценивает слабые приграничья, но не фокусит игрока искусственно; баланс стартовых ресурсов/позиций должен быть симметричным по силе, не обязательно по расположению.

## 7. Ходы и победа

`Round` — игрок, AI-1, AI-2 делают по 3 AP; затем `ResolveRound`: доход, upkeep, строительство, осады, эхо, проверки победы и начисление очков. Не разрешать окончания хода, если у фракции есть непоказанный конфликт: допустимо предупреждение, но не блокировка.

**Результат партии:** максимальная длина **20 полных раундов**. Ранняя победа — одна фракция владеет **≥70% от всех 54 регион-эпох** на конец раунда (маловероятно; основной результат по очкам). На 20-м раунде победа по `victoryScore`:

- +2 за каждый контролируемый регион-эпоху;
- +3 за город ур.2, +6 ур.3, +10 ур.4 (вместо +2? **дополнительно** к территории, по самому высокому достигнутому уровню);
- +2 за каждую технологию;
- +1 за каждое активное echo-бонусное соединение на контролируемом будущем/настоящем регионе (но cap ≤12 за всю империю);
- +1 за 3 полных единицы любого из food/wood/ore/energy/knowledge на конец, максимум 10 от ресурсов.

Проверка при `EndRound`, ничья → число контролируемых ключевых choke points → число городов → фиксированный seeded tie-breaker. Если игрок не контролирует ни одной столицы в любой эпохе **и** не имеет армии/аванпоста, поражение сразу. UI показывает остающиеся раунды, счёт приблизительно и лидера.

## 8. AI: два соперника, реальные решения

ИИ-1 `expansionist`, ИИ-2 `defensive-builder`. В каждом своем ходу ИИ строит пул легальных `GameCommand` и ранжирует по стратегической функции, не обходит валидацию:

`score(command) = tacticalGain + resourceNeed + temporalEchoGain + strategicChokepointBonus + defenseUrgency - expectedLoss - exposureCost + seededNoise(0..0.2)`.

Приоритеты: `expansionist`: 40% расширение, 30% военное давление, 20% экономика, 10% оборона/наука; `defensive-builder`: 25% расширение, 20% давление, 30% экономика, 25% оборона/наука. Проценты — веса поведения, не жёсткая вероятностная раздача; ИИ делает полезные команды и корректно завершает ход даже без доступных ресурсов.

Требования: ИИ не имеет скрытых ресурсов, использует те же AP и правила; ни одна итерация не превышает 2000 проверок команд или ~50 ms на обычном устройстве на один ход (задать бюджет в тестах); две ИИ-фракции конфликтуют между собой, а не образуют вечный союз против игрока. AI ход можно быстро пропускать без изменения результата. Показать короткие итоги хода.

## 9. UI / UX и графика

### 9.1. Общее правило

**Карта — почти весь экран.** Без постоянного сайдбара, модальных окон на каждое действие и тяжёлого HUD. Верхняя полоса компактная, нижняя — компактная; объекты открывают временную карточку. Простое 2D: изометрия **не требуется**, важна читаемость на телефоне. По дизайну — чистые формы, ограниченная палитра, красивые масштабирующиеся обозначения, без тяжёлых 3D-ассетов.

### 9.2. Desktop landscape

- 16:9: верхняя строка ~48–56 CSS px (название, 3 эпохи, сокращённые ресурсы, round/AP, меню), нижняя ~56–64 CSS px (`City`, `Build`, `Army`, `Research`, `End Turn`). Карта = оставшаяся центральная площадь (примерно ≥85% высоты при 1080p) и 100% ширины.
- При выборе объекта маленькая контекстная панель привязана к нижней/боковой кромке максимум 300×240 px; **не постоянная боковая колонка**. Панель сворачивается без потери выбора.
- Клавиатура: Escape закрывает карточку, Space центрирует на столице или в будущем — пауза (в v0.1 не замораживает раунд), колёсико зум; горячие клавиши 1/2/3 эпохи, E конец хода с подтверждением.

### 9.3. Mobile portrait

- Тестовые viewports **390×844, 360×800, 320×568**. Не требовать landscape, не включать orientation lock.
- Верхняя панель ≤72 CSS px с компактными отображениями эпох, round/AP; ресурсы в раскрывающемся поповере. Нижняя ≤74 CSS px с кнопками по 44 CSS px минимум (или прокручиваемая строка действий).
- Контекстный **bottom sheet**, высота **25–35% экрана**, когда нужен; по умолчанию скрыт. Позволяет свайпнуть вниз/закрыть, не закрывает весь экран. При 320×568 показать 2–3 ключевые действия, остальные — через раскрытие.
- Не менее **44×44 CSS px** для активных touch areas, подходящие отступы между элементами. Учесть `env(safe-area-inset-*)`. Меньшая визуальная иконка может иметь 44px хитбокс.
- pinch и pan не должны случайно активировать строительство; drag threshold 8 CSS px; нет hover-only механик; подсказки доступны по tap.
- При открытии клавиатуры игровое поле не должно прыгать; main game занимает `100dvh`, fallback `100vh`.

### 9.4. Чёткое визуальное развитие

**Города 4 ур.**: L1 домик; L2 группа из 2–3 домов/ограждение; L3 укреплённый город; L4 столица с высоким центральным строением. Менять силуэт и масштаб **в каждой эпохе**. Past дерево/солома, Present камень/кирпич, Future металл/светящиеся элементы.

**Армии:** 2 типа × 3 эпохи × 4 уровня = **24 отличимых варианта** рисунков (можно процедурно менять шлем, плащ, оружие, броню, не нужно 24 внешних PNG); каждый вариант — маленькие **человекообразные фигуры**, не эмодзи. Цвет владельца — дополнительная окантовка, не заменяет снаряжение.

**Окружение:** простой стилизованный лес (группы крон), горы, река, мосты, дороги, ресурсы и хорошо видимые полигоны. Прозрачная цветовая заливка территории владельца, сильная граница выделенного региона, текстовый tooltip. Опциональные короткие анимации: марш, смена владельца, атака, осада, строительство.

### 9.5. Объяснимость

Любая кнопка показывает цену/эффект и почему недоступна. Первый матч: 5 коротких подсказок («Выбери эпоху», «Захвати нейтральный регион», «Построй ферму», «Отправь армию», «Заверши ход»). Подсказки пропускаются, доступны в «Как играть». Сохранить выбор уменьшенных анимаций, громкость (можно начать без звука), масштаб UI, язык RU/EN если реализован.

## 11. Модель данных / команды (контракт)

```ts
type Epoch = 'past' | 'present' | 'future';
type FactionId = 'player' | 'rivalA' | 'rivalB';
type RegionId = string;
type ResourceId = 'food'|'wood'|'ore'|'energy'|'knowledge'|'influence';
type Resources = Record<ResourceId, number>;
type Terrain = 'plain'|'forest'|'mine'|'farmland'|'river_crossing'|'mountain_pass'|'city'|'ruins';
type BuildingKind = 'farm'|'lumberMill'|'mine'|'academy'|'powerPlant'|'watchtower'|'wall'|'barracks'|'outpost';
type UnitClass = 'infantry'|'ranged';
interface RegionGeometry { id: RegionId; x: number; y: number; polygon: [number,number][]; neighbors: RegionId[]; terrain: Terrain; isChokepoint: boolean; }
interface Building { id:string; kind:BuildingKind; level:1; completed:boolean; completionRound:number; }
interface City { level:1|2|3|4; isCapital:boolean; }
interface RegionEpochState { owner:FactionId|null; city:City|null; buildings:Building[]; siege:Siege|null; }
interface Army { id:string; factionId:FactionId; epoch:Epoch; regionId:RegionId; unitClass:UnitClass; level:1|2|3|4; hp:number; movementRemaining:number; undersupplied:boolean; }
interface FactionState { id:FactionId; resources:Resources; researched:string[]; armies:Army[]; actionPoints:number; comebackUsed:boolean; }
interface GameState { schemaVersion:1; gameVersion:'0.1.0'; seed:number; rngState:number; phase:'planning'|'resolution'|'finished'; round:number; activeFaction:FactionId; map:RegionGeometry[]; regionEpoch:Record<Epoch,Record<RegionId,RegionEpochState>>; factions:Record<FactionId,FactionState>; events:GameEvent[]; result:GameResult|null; }
// Каждая команда включает commandId (unique), player/factionId, epoch и параметры.
type GameCommand =
  | {type:'claimNeutral'; factionId:FactionId; epoch:Epoch; target:RegionId}
  | {type:'construct'; factionId:FactionId; epoch:Epoch; region:RegionId; building:BuildingKind}
  | {type:'upgradeCity'; factionId:FactionId; epoch:Epoch; region:RegionId}
  | {type:'recruit'; factionId:FactionId; epoch:Epoch; region:RegionId; unitClass:UnitClass}
  | {type:'moveArmy'; factionId:FactionId; epoch:Epoch; armyId:string; destination:RegionId}
  | {type:'attack'; factionId:FactionId; epoch:Epoch; armyId:string; target:RegionId}
  | {type:'upgradeArmy'; factionId:FactionId; epoch:Epoch; armyId:string}
  | {type:'research'; factionId:FactionId; techId:string}
  | {type:'endTurn'; factionId:FactionId};
interface CommandOutcome { accepted:boolean; state:GameState; events:GameEvent[]; rejectionReason?:string; }
interface SimulationClock { mode:'turn'|'realtime'; simulationTime:number; advance(deltaUnits:number):void; }
```

Все `GameCommand` проходят `validate → apply → append events`. UI только диспатчит команды, никогда не меняет `GameState` непосредственно. `getLegalCommands(state,faction,selection)` используется игроком и ИИ. `GameEvent` — структурированная запись (`kind, round, epoch, payload, ordinal`) пригодная для анимации/реплея/будущих таймеров. Отображение генерируется из GameState через selectors. Дополнительные поля допустимы, но не ломать сериализуемость.

### 11.1. Конвейер симуляции

```text
UI/AI intention
    ↓
validateCommand(state, command)
    ↓
applyCommand(state, command, seededRng) → newState + domainEvents
    ↓
if endTurn: nextFactionOrResolveRound()
    ↓
resolveIncome → resolveConstruction → resolveSieges → recalcEcho → checkVictory
    ↓
selectors → Phaser renderer + DOM HUD
```

Никаких `Date.now()` и `Math.random()` в правилах. RNG — xorshift32 / mulberry32, seed сохраняется в state, расход random streams порядок-зависимый и тестируется. State следует клонировать или менять централизованно в чистом reducer. При переигрывании одного массива команд на одинаковом seed результат побитово одинаковый для сериализуемых числовых полей.

### 11.2. Важные инварианты

1. Сумма ресурсов не отрицательна; строительство и атака не должны тратить AP дважды.
2. Владение регионом в эпохе — одно значение; `regionEpoch[epoch]` всегда содержит все 18 регионов.
3. Не бывает армии, прикреплённой к несуществующему региону или эпохе.
4. AI и игрок используют один `validateCommand`, не обходя правила.
5. Каждый новый полноценный раунд запускает начисление ресурсов **ровно один раз**.
6. Состояние загрузки не должно запускать повторное начисление дохода.
7. Все временные эхо пересчитываются односторонне, не создают владения, и не начисляют бонус при чужом контроле в будущей эпохе.
8. Истощение AP не препятствует переключению эпохи / просмотр информации / управлению камерой.

## 12. Save, performance, accessibility

- Автосохранение после каждого полного раунда и перед закрытием вкладки best-effort; ручное Save/Load в меню. Формат `stolenAges.save.v1`, поля `schemaVersion, state, timestamp, checksum?`; ошибки чтения не приводят к пустому экрану, предлагается новый матч.
- На `document.visibilitychange` **не начислять** симуляционное время; игра пошаговая. В будущей версии — автоматическая пауза.
- Цель: 60 FPS на среднем ПК, 30–60 FPS на современном смартфоне; приемлемость проверить реальными измерениями. До 18 регионов и ~20–30 визуальных объектов на активной эпохе, объекты вне viewport можно не рендерить. Никакой бесконечной анимации или тысячи DOM-узлов.
- Не использовать звуковые эффекты без возможности отключить. Контраст владений дублировать формой границ; текст не зависит от цвета. Управление клавиатурой для меню и основных кнопок, aria-label для DOM controls.
- Уважать `prefers-reduced-motion`; отключаемые эффекты; браузерный fullscreen опционален, **не обязателен**. PWA можно после v0.1.

## 13. Длительность партии — модель и критерии

**Это целевые оценки, не реальные данные.** Предлагаемая модель: 20 раундов × средний активный отрезок 50–65 сек (≈ 3 решения × 12–18 сек плюс обзор/анимации/AI) = ~17–22 мин на ПК у опытного игрока. Дополнительные длинные паузы, выбор эпох и обучение увеличивают время.

| Игрок | ПК landscape | Смартфон portrait |
|---|---:|---:|
| Опытный | 17–22 мин | 20–27 мин |
| Новичок | 25–35 мин | 28–40 мин |
| Целевой медианный матч после плейтестов | 20–25 мин | 22–29 мин |

Если матчи идут 40+ минут у опытных, нужно сократить до 16 раундов или количество AP, увеличить темп завершения и/или ускорить UI/AI. Если <12 минут — уменьшить snowball и повысить значимость долгосрочных инвестиций. Игровая телеметрия **локально, без отправки данных**: `matchDuration, completedRounds, turnsPerEra, apSpentByKind, gameEndReason, aiTime, crashCount`. Экспортировать JSON по нажатию для добровольных плейтестов.

### 14.2. Acceptance tests (обязательно автоматизировать где возможно)

1. `newGame(seed=12345)` создаёт 18 регионов × 3 эпохи, все стартовые столицы, 3 фракции, непересекающиеся стартовые владельцы в каждой эпохе.
2. Игрок тратит 3 AP, 4-я команда отклонена; переключение эпох бесплатное.
3. Мирный захват соседней нейтральной области списывает AP/ресурсы, меняет владельца; без смежности/ресурсов — отклонён.
4. Build Farm/Outpost/Watchtower виден на карте, правильно стоит и влияет на доход/оборону; отменённая команда не тратит ресурсы.
5. Farm в Past даёт бонус в Present лишь при совпадающей фракции-владельце; бонус пропадает при потере региона, не дублируется из-за перерисовок.
6. Город 1→4 меняет мощность и силуэт, превышение 4 отклоняется.
7. Army recruit/move/upgrade/attack работают с AP, эпохой, смежностью и запасами, есть победа, отступление, уничтожение и осада.
8. Повтор одного seed и набора действий даёт одинаковые `GameState` и бой; сохранение/загрузка сохраняют seed и RNG state.
9. Два AI делают только допустимые команды, заканчивают ход, 100 партий можно симулировать headless до результата (нет зацикливания).
10. Победа/поражение/конец 20-го раунда показывает корректный экран, можно начать заново.
11. Контекстные действия доступны tap на телефоне, pan не вызывает случайный attack, pinch/wheel масштабирует карту, она не перекрыта боковой панелью.
12. 320×568 и 390×844 portrait: кнопки доступны, нет горизонтальной прокрутки UI, нижняя панель не заходит за safe-area, карта занимает большую часть свободной площади.
13. Page refresh загружает текущую игру, сломанный localStorage не вызывает белый экран.
14. `npm ci && npm run typecheck && npm run test && npm run build` проходит на чистой CI-машине; GitHub Pages URL обслуживает ассеты из `/stolen-ages/`.
15. В README есть понятный запуск, версия, текущее ограничение offline/localStorage, описание двух ИИ и трех эпох; нет фиктивных claims о multiplayer/RTwP.

## 15. Риски и решения

- **Слишком сложные три эпохи:** переключатель и «эхо» работают, но в v0.1 нет телепорта армий и автоматической смены будущих владельцев. Это сознательное MVP-ограничение.
- **Слишком долгий матч:** лимит AP и 20 раундов, score win; реальные целевые числа корректировать после тестов.
- **Слишком простой бой:** добавить разные местности/укрепления/осаду и прозрачный прогноз, не вводя микроменеджмент RTS.
- **Тяжелый мобильный UI:** пустой экран карты по умолчанию, маленький top HUD, контекстный sheet по требованию.
- **Перекос ИИ:** равные ресурсы, общий validator, headless симуляции, seed-сценарии, метрики win rate.
- **Сломанный Pages:** Vite base, GitHub Actions, проверка URL и навигации.
- **Future RTwP:** чистое командное ядро, симуляционные события, `SimulationClock`, скорость/пауза не реализуются в v0.1; архитектуру см. отдельный документ.

## 16. Готовность к релизу

**Release `v0.1.0` принимается только если** можно пройти полноценную игру в браузере от меню до экрана результатов, с двумя ИИ, работающими экономикой, территориальными захватами, развиваемыми городами, отрядами и тремя эпохами; desktop и portrait mobile, сохранением, зелёными тестами, GitHub Pages. При провале критерия — это milestone/alpha, а не завершённая версия.
